# 单人本地库存版与 GitHub Pages 静态部署设计

## 1. 目标

把现有“衣架仓库管理”改造成适合单人使用的静态网页应用，部署到 GitHub Pages 后，客户可以直接用手机浏览器访问，不依赖云服务器，也不要求电脑持续开机。

静态部署不等于删减业务功能。本次改造必须保留：

- 商品系列、商品型号、货号、颜色、包装规格和最低库存；
- 库存查询和库存状态提示；
- 入库、出库、调整三类库存操作；
- 每一次库存变动的编号、时间、操作类型、备注、操作前数量、变动数量、操作后数量；
- 出入库记录筛选和查看；
- 商品系列、型号和出入库记录的手动删除入口；
- 现有的“只能删除最新一条库存变动，删除后恢复操作前库存”的安全规则；
- 手机端布局、PWA 添加到主屏幕和离线继续使用；
- 数据导出和导入备份。

## 2. 已确认的使用边界

### 2.1 使用人数和数据范围

- 只服务一个人使用。
- 数据默认保存在当前手机的当前浏览器中，不同步到其他设备。
- 不再依赖在线账号、在线会话和 PostgreSQL 才能正常使用。
- 当前方案不提供多人协作、云端同步、跨设备实时共享和服务端权限管理。
- 本地数据属于客户自己的设备数据，必须通过备份功能保护，不能把客户库存数据提交到公开 GitHub 仓库。

### 2.2 数据安全提示

网页清除站点数据、卸载浏览器、切换浏览器或更换手机，都可能导致本地数据不可见。因此设置页面必须明确显示“请定期导出备份”，并提供可恢复的 JSON 备份。

首次切换到本地版前，先从当前 PostgreSQL 数据库导出一次 JSON，再在手机或浏览器中导入；不允许直接覆盖或删除现有数据库数据。备份文件不纳入 Git，也不发布到 GitHub Pages。

## 3. 总体架构

### 3.1 构建和部署

- Next.js 使用 `output: "export"` 生成 `out/` 静态文件。
- GitHub Actions 在 `main` 分支更新时构建并发布 `out/` 到 GitHub Pages。
- 站点使用项目路径 `/hanger-warehouse/`，生产访问地址为：
  `https://zhonghekai393-del.github.io/hanger-warehouse/`
- 不再把 `app/api` 中依赖 PostgreSQL、Cookie 会话或 POST/DELETE 服务端接口作为生产运行时的一部分。
- 静态页面中的写入操作全部通过浏览器 IndexedDB 完成。

Next.js 官方静态导出文档说明，静态导出可部署到任意静态服务器，但服务端运行时能力不能随静态文件一起运行。因此现有服务端 API 必须改为本地数据层，不能只在配置中打开静态导出后继续调用原 API。

### 3.2 本地数据层

新增一个小型本地仓库层，页面只依赖仓库层，不直接操作 IndexedDB。仓库层负责初始化数据库、读写数据、事务和业务错误。

推荐的数据表（IndexedDB object stores）：

- `products`：商品系列；保留 `id`、`name`、启用状态和创建时间；
- `variants`：商品型号；保留系列 ID、型号、货号、颜色、包装规格、最低库存和启用状态；
- `warehouses`：仓库；单人版默认只创建一个“主仓库”，保留结构以兼容已有业务；
- `inventory`：型号与仓库的当前库存；以型号 ID和仓库 ID组成稳定键；
- `movements`：所有入库、出库和调整记录，保存操作前后余额；
- `settings`：数据库版本、当前用户显示名和应用设置等元数据。

所有记录使用稳定 ID，时间使用 ISO 字符串，数量使用整数。库存数量不能为负数，入库和出库均通过同一个库存变更事务完成。

### 3.3 事务规则

`applyMovement` 必须在同一个 IndexedDB `readwrite` 事务中完成：

1. 读取型号和当前库存；
2. 校验型号仍启用、数量为正整数、出库后库存不为负；
3. 计算 `beforeQuantity`、`delta`、`afterQuantity`；
4. 更新 `inventory`；
5. 写入 `movements`，生成唯一的本地记录编号；
6. 任意一步失败时，整个事务回滚。

删除出入库记录时：

- 只能删除该型号、该仓库最新的一条记录；
- 删除前再次读取当前库存和最新记录，防止页面停留期间误删；
- 删除成功后把库存恢复为被删记录的 `beforeQuantity`，再删除记录；
- 删除较旧记录返回明确的中文错误“只能删除最新一条记录，请先删除后面的记录”；
- 不提供静默批量删除，不改变用户未选择删除的记录。

商品删除仍采用停用方式，避免已有出入库记录失去关联；型号删除后不再出现在新增库存操作选择中，但历史记录继续可查看。

## 4. 页面和路由方案

GitHub Pages 静态导出不能为运行时新建的 ID 动态生成服务端页面，因此不再依赖 `/products/[id]`、`/products/[id]/variants/[variantId]` 这类运行时动态路由。

保留用户能理解的页面入口，但把详情选择改成查询参数或页面内状态：

- `/dashboard`：首页概览；
- `/inventory`：库存查询；
- `/movements`：出入库记录和筛选；
- `/products`：商品系列和型号管理；
- `/products/detail?id=...`：商品系列详情；
- `/products/variant?id=...`：型号详情及库存操作；
- `/settings`：本地数据导出、导入和应用说明；
- `/login`：静态版不再调用服务端登录。若保留入口，应改成说明页或本地解锁入口，不能伪装成云端账号登录。

页面首次加载时由客户端仓库层读取 IndexedDB，再渲染加载中、空数据、正常数据和错误状态。不能在静态构建阶段读取客户本地数据。

首页重定向不能使用服务端 `redirect()` 作为静态运行依赖，应改成客户端导航或静态链接，确保直接访问 GitHub Pages 根路径时可用。

## 5. 备份、迁移和恢复

### 5.1 本地版备份格式

导出 JSON 顶层包含：

- `format`: 固定格式名称；
- `version`: 备份格式版本；
- `exportedAt`: 导出时间；
- `products`、`variants`、`warehouses`、`inventory`、`movements`、`settings`。

导出文件名包含日期，例如 `衣架仓库备份-2026-10-06.json`。导出只复制数据，不清空当前数据。

### 5.2 导入规则

- 选择文件后先校验格式版本、必填字段、ID 引用和数量范围；
- 校验失败时不写入任何数据，并显示具体中文错误；
- 导入前显示数据概要（系列数、型号数、库存记录数、出入库记录数）；
- 用户确认后在一个 IndexedDB 写事务中替换本地数据；
- 导入过程中失败时不留下半套数据；
- 导入成功后刷新页面并显示导入时间和记录统计；
- 导入不会自动上传 GitHub、Render 或任何远程服务。

### 5.3 现有 PostgreSQL 数据迁移

在切换生产页面前，使用一次性本地脚本读取当前数据库，生成与本地版相同格式的 JSON。脚本只用于迁移，不在静态前端打包，也不把数据库连接串或备份文件提交到仓库。

迁移验收必须比较：商品系列数量、型号数量、当前库存数量和出入库记录数量；还要抽查至少一条入库、一条出库和一条删除后恢复场景。若迁移文件生成失败，现有数据库保持不动。

## 6. PWA 和手机使用

- manifest 的 `start_url`、图标和资源路径使用 `/hanger-warehouse/` 基础路径；
- Service Worker 注册和缓存路径同样使用项目基础路径；
- 首次联网打开后缓存静态应用文件；
- 后续即使暂时断网，也能打开已缓存页面并读写 IndexedDB；
- Service Worker 更新采用新版本缓存名，避免旧 JS 和新 HTML 混用；
- 页面显示当前是否有本地数据以及最近一次备份时间；
- 手机端保留底部导航，表单按钮和删除确认适合触摸操作。

## 7. 测试和验收

### 7.1 纯业务测试

用现有测试框架覆盖库存规则：

- 入库：0 加数量得到正确余额；
- 出库：余额足够时成功，余额不足时失败；
- 调整：正负调整都保存前后余额；
- 删除最新记录：库存恢复到被删记录前余额；
- 删除旧记录：返回中文业务错误且库存不变化；
- 停用商品或型号后不能新建库存操作，但历史记录可读。

### 7.2 本地仓库测试

- 建库和默认主仓库初始化只执行一次；
- 商品、型号和库存读写可用；
- 库存与记录在同一事务中成功或一起失败；
- 导出后导入，数据数量、ID、库存和记录前后余额一致；
- 非法备份文件不会污染已有数据。

### 7.3 浏览器和静态部署测试

- `pnpm lint`、`pnpm typecheck`、`pnpm test --run` 通过；
- `pnpm build` 成功生成 `out/`，且不依赖数据库连接；
- 检查 `out/index.html`、manifest、Service Worker 和项目基础路径；
- GitHub Pages 页面能在手机浏览器打开；
- 手机浏览器完成新增型号、入库、出库、查看记录、删除最新记录和导出；
- 重新打开页面后数据仍在；
- 导入备份后数据恢复；
- 断网后，已缓存页面仍能完成本地读取和库存写入。

### 7.4 验收标准

满足以下条件才认为静态版完成：

1. 不需要电脑开机、不需要 PostgreSQL、不需要 Render，直接访问 GitHub Pages 地址即可使用；
2. 入库、出库、调整和出入库记录全部可用；
3. 删除由用户主动点击决定，并且保留最新记录删除保护；
4. 当前数据库数据已经导出并能导入本地版，数量和抽查结果一致；
5. 手机端能安装到主屏幕，刷新和短暂断网不会丢失本地数据；
6. GitHub 仓库中没有 `.env`、数据库密码、客户库存备份或其他私密数据。

## 8. 不在本次范围内的内容

- 多人同时编辑和实时同步；
- 云端数据库、云端账号和密码找回；
- 跨手机自动同步；
- 服务端审计日志和远程权限控制；
- 自动把本地数据备份到 GitHub；
- 在没有备份的情况下自动清空或重置库存。
